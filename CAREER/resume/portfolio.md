## Notes for the portfolio rebuild

You mentioned the portfolio needs updating. For a DevOps/Platform target, a
portfolio is not a pretty site — it is **evidence of systems you have run**:

- Public repos with real Terraform/K8s config, good READMEs, and an
  architecture diagram
- A write-up of something that **broke** and how you fixed it (pull these from
  `PRACTICE/<topic>/problems.md` — that file is your source material)
- CI that visibly runs on your repos
- Cost/tradeoff reasoning written down, not just "I used X"

One deeply documented system beats six half-finished ones. Interviewers read
one repo, and they read the README first.
